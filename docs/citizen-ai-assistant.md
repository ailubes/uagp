# RFC-UAGP-0003 — Citizen AI Assistant (дослідницький прототип)

**Статус: Draft 0.1, 22 листопада 2026.** Частина UAGP; залежить від громадянського протоколу RFC-UAGP-0002 у PR #8 і каркаса двох громад у PR #7.

## Призначення

Citizen AI Assistant допомагає мешканцям описати суспільну проблему без юридичної чи технічної підготовки, уточнити бажаний результат, сформулювати можливі альтернативи та визначити, що потрібно перевірити. Він **не** є органом влади, не має повноважень подавати офіційні звернення, ухвалювати рішення, публікувати особисту інформацію чи змінювати Harness.

Спочатку реалізовано **read-only** асистента, який повертає структуру пропозиції, а не змінює її. Редагування автором відбувається окремим існуючим шляхом `/v1/civic/drafts/{id}/clarify`; остаточне підтвердження потребує окремого preview fingerprint і явної дії автора. Навіть переконливий текст AI не замінює згоду.

## Режими

**Локальний безмодельний режим (`local_rules`)** доступний без інтернету й ключів провайдера. Він ставить базові уточнювальні питання на основі полів чернетки. Це детерміновані правила, а не приховане наслідування роботи мовної моделі.

**Модельний режим (`configured_model`)** використовує явно налаштований OpenAI-compatible endpoint через змінні `UAGP_AI_BASE_URL`, `UAGP_AI_MODEL` і, якщо endpoint віддалений, `UAGP_AI_API_KEY`. Дані надсилаються тільки за явними параметрами кожного запиту `use_model=true` та `allow_external_processing=true`. Сервер не надсилає ідентифікатор автора, його ключ або ідентифікатор справи; проте *текст самої проблеми* може містити персональні відомості, тому не слід вмикати цей режим для справжніх громадян без оцінки приватності, юридичної підстави та відповідного повідомлення користувачу.

## API

```http
GET /v1/assistant/capabilities
POST /v1/assistant/drafts/{draft_id}/respond
X-UAGP-Author-Key: <demo-secret>
Content-Type: application/json
```

Приклад тіла запиту:

```json
{
  "message": "Допоможи зрозуміти, як покращити пересадку з автобуса на потяг",
  "history": [],
  "use_model": false,
  "allow_external_processing": false
}
```

Відповідь містить `assistant_message`, `clarification_questions` (до трьох), `proposed_desired_outcome`, `proposed_solution`, `procedure_hint`, `evidence_questions`. Додаткові поля відхиляються структурною валідацією. Відповідь також завжди пояснює `draft_unchanged=true`, `requires_author_confirmation=true`, `official_submission=false`.

## Межі довіри

Асистентові не передаються токени повноважень, він не має доступу до ToolGateway і не володіє API, які змінюють статус справи. Вміст діалогу вважається недовіреним. Модельний провайдер повертає структурований JSON, який перевіряється Pydantic; у разі помилки сервіс відмовляє без демонстрації внутрішньої відповіді моделі. Модель не може назвати себе адміністративним органом і не є джерелом правового висновку.

Текст підказки (system instructions) вимагає нейтрального уточнення та забороняє вигадувати юридичні факти й агітувати. Одна лише підказка не гарантує безпеки: фактичний захист забезпечує відсутність привілейованих викликів та незалежність громадянського протоколу.

## Конфіденційність і загрози

Тестовий endpoint моделі не повинен використовуватися для приватних реальних справ. Зовнішні API можуть зберігати передані тексти відповідно до власних умов. Наразі відсутні повноцінна система видалення приватних діалогів, управління дозволами на обробку, перевірена цифрова ідентичність, контроль частоти викликів, незалежне оцінювання упереджень та юридично значуща маршрутизація.

Провайдерський URL задається лише оператором через конфігурацію. Зовнішній HTTP без TLS відхиляється, а локальний HTTP дозволяється лише для loopback. Для виробничого використання також потрібні мережевий egress allowlist, протидія DNS rebinding і проксі, моніторинг вартості та захист від exfiltration.

## Перевірка

Тести повинні підтвердити, що без секрету автора немає доступу до чернетки; за відсутності окремої згоди немає зовнішнього модельного виклику; неналежна відповідь моделі відхиляється; локальний режим доступний без LLM; підтверджена справа не змінюється; запит не приймає службових команд, а відповідь моделі ніколи не означає юридичного подання.

## Порядок подальшої розробки

Наступними задачами є машиночитний повний опис проблеми, відділення фактів від гіпотез з доказами, різні мови та доступність, безпечний персональний чат із контрольованим зберіганням історії, пошук схожих ідей лише в дозволених публічних даних, оцінка альтернатив і симуляція їхніх наслідків та окрема перевірка правового маршруту.

**Поточний код — sandbox, а не готовий Citizen AI Assistant для реального населення.**
