# Реєстр відкритих рішень спільноти

Це публічний перелік **рішень, які пропонуються або потребують затвердження**, а не доказ, що відповідні інституції вже існують.

| Питання | Робоча позиція | Що потрібно зробити | Статус |
| --- | --- | --- | --- |
| Незалежна ідентифікація | Окремий self-hosted OIDC issuer UAGP, жодної інтеграції з Wesfin ID | Розглянути [ADR-010](../identity/ADR-010-independent-self-hosted-oidc.md), визначити оператора й технічний план | Вимога сформульована, не розгорнуто |
| Ліцензії | Apache-2.0 для коду; CC BY 4.0 для оригінальної документації | [LICENSE](../../LICENSE), [LICENSE-DOCS](../../LICENSE-DOCS.md), [LICENSING](../../LICENSING.md), перевірка прав внесків | Зафіксовано в репозиторії; контроль прав триває |
| Участь без GitHub | Не робити GitHub обов'язковим для громадян | Безпечний доступний канал для ідей, модерація, privacy review | Не реалізовано |
| Хартія | Відкрита до поправок і критики | Публічний RFC, фіксація заперечень, правова перевірка | Процес запропоновано |
| Правова межа | Ніяких офіційних звернень, поки немає належного мандата | Окрема юридична експертиза й партнерство | Обмеження чинне для дослідницького проєкту |
| Публічний запуск | Спочатку правила, безпека, доступність і відповідальні | [Контрольний перелік](PUBLIC-LAUNCH-CHECKLIST.md) | Не готово |
| Роль AI | Допомагає формулювати, не приймає владних рішень | Формальні дозволи, розділений ToolGateway, незалежне тестування | Концепція, демонстратори в PR |
| SG-01: жива практика | Спільна робота з 2–3 добровільними активними спільнотами, спочатку без вимоги нового ПЗ | [Living Practice 90](../strategy/LIVING-PRACTICE-90.md), відбір партнерів, baseline, правовий огляд, координатори | Стратегічна програма підготовлена, партнери й старт не підтверджені |
| Співрозвиток технологій | Додавання статті 88-2 до робочої Хартії UAGP | Публічне обговорення та незалежна правова рецензія відповідного PR | Додано в робочу редакцію, PR на перегляді |
| Управління спільнотою | Прозорі рішення, не є представницькою владою | Погодити ролі, порядок апеляцій, конфлікти інтересів, фінансування | Проєкт правила |

Після кожного рішення потрібно додати конкретне посилання на Issue/PR/RFC, дату, відповідальний огляд, альтернативи й аргументи меншості. Переказ AI не є доказом погодження.
