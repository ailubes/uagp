# Як долучитися до UAGP

Нам потрібні не тільки програмісти. Якщо ви знаєте, що можна покращити у своїй громаді, вмієте перевіряти факти, розумієте право, захищаєте права людей, створюєте доступні інтерфейси або можете поставити незручне запитання – ваша участь важлива.

Почніть із [путівника спільнотою](docs/community/README.md). Наявність GitHub-акаунта потрібна для поточної публічної дискусії на GitHub, але не має бути постійною умовою роботи UAGP. Відкритий альтернативний канал без GitHub ще не готовий.

## Для громадян

Заповніть [шаблон проблеми](docs/community/PROPOSAL-TEMPLATE.md) і, тільки після власної перевірки того, що текст безпечно публікувати, створіть [публічний Issue](https://github.com/ailubes/uagp/issues/new/choose). Участь у UAGP не є поданням звернення до державного органу. Не публікуйте приватних даних чи чужих історій без дозволу.

Ви можете надіслати одну лише проблему й очікуваний результат без готового рішення. Якщо правова рамка незрозуміла, прямо позначте невизначеність. Рецензенти не повинні вимагати від громадянина писати як юрист або розробник.

## Для фахівців і розробників

Оберіть [завдання](https://github.com/ailubes/uagp/issues), перевірте попередні обговорення, напишіть в Issue короткий план роботи. Для технічної зміни створюйте PR із описом проблеми, альтернатив, тестів, ризиків, наслідків для прав людини, сумісності та повернення попередньої версії. Чутливі дані й секрети заборонено включати в Git.

Для зміни прав або керівного контуру Harness потрібні окрема правова підстава, безпекова оцінка, незалежна перевірка й заборона самостійного затвердження змін моделлю. Наразі всі повноваження в коді є лабораторними.

## Для дослідників і громадських організацій

Пропонуйте публічні, знеособлені кейси з перевірними джерелами, правові рецензії, аналіз витрат і правових альтернатив, доступні пояснення. Пропозиція «пілоту» сама по собі не є домовленістю про використання персональних даних або втручання в роботу органу влади.

## Як ми розглядаємо пропозиції

[Процес громадянських ідей](docs/community/PROPOSALS.md) відділяє проблему, обговорення, перевірку фактів, експеримент і рішення про включення до проєкту. [Поправки до Хартії](docs/community/CHARTER-REVIEW.md) мають окремий маршрут. Аргументована незгода з рішенням дозволена, а статус злиття GitHub-коду не створює політичного мандата.

## Мова, доступність, повага

Основна мова документації – українська; англомовні внески прийнятні, якщо поруч надано або планується зрозуміле українське пояснення. Ми заохочуємо доступні формати, просту термінологію та підтримку користувачів без платних AI. Дотримуйтеся [Кодексу поведінки](CODE_OF_CONDUCT.md) й [правил модерації](docs/community/FACILITATION.md).

## Ліцензії та авторське право

Оригінальний програмний код, тести й машинозчитувані схеми – [Apache-2.0](LICENSE). Хартія, RFC-пояснення та оригінальна документація – [CC BY 4.0](LICENSE-DOCS.md). Детальна [політика ліцензування](LICENSING.md).

Перед поданням PR переконайтеся, що маєте право надати відповідну ліцензію на власний внесок. Авторські права залишаються за авторами. Внески в код після прийняття надаються на умовах Apache-2.0, а текстові внески, інкорпоровані в оригінальну документацію, – на умовах CC BY 4.0. Не копіюйте чужі матеріали, закриті дослідження чи персональні дані без законних дозволів. За сумніву maintainer повинен уточнити умови до злиття.

## Безпека

Не публікуйте реальні державні особисті справи, токени, паролі, приватні медичні чи ідентифікаційні дані, секретні вразливості та захищені державні відомості. Використовуйте [SECURITY.md](SECURITY.md). Вхід через UAGP OIDC ще не реалізований; чинні тестові ключі – тільки для локальних експериментів.
