# UAGP Public Workspace – WEB-001

**Протокол алгоритмічного врядування України (UAGP)**. Перший незалежний, вебзастосунок із публічним каталогом і закритою чергою для співпраці над протоколом. Це не офіційний державний сервіс і не розгортання дослідницького FastAPI /ui.

## Запуск

Потрібно Node.js 22.13+ (рекомендовано останній 22 LTS або новіший підтримуваний LTS) і npm.

    cd web
    npm ci
    cp .env.example .env.local
    npm run dev

Відкрити http://localhost:3000. За замовчуванням сервер читає публічний GitHub API. GITHUB_TOKEN необов'язковий; використовуйте тільки мінімальний серверний дозвіл на читання публічних даних. Не вказуйте секрет у NEXT_PUBLIC_*. Запуск у режимі знімка даних:

    UAGP_DATA_MODE=snapshot npm run dev

Режим знімка завжди має видимий час і попередження. Це не симуляція активності громадян.

## Реалізовані маршрути

- / – огляд, актуальні питання, запропоновані зміни та маршрути участі.
- /issues та /issues/[number] – пошук за номером, назвою, описом, напрямом, станом, призначенням; деталі й справжній GitHub.
- /solutions та /solutions/[number] – розділені статуси PR: чернетка, до розгляду, злито, закрито без злиття. Згадки #номер у тексті не видаються за перевірені залежності.
- /charter – читання Хартії з main і посилання на окремі поправки.
- /community – напрями роботи, координація та правила.
- /strategy – SG-01 Living Practice 90, матеріали і відкриті питання. Партнери й старт не вважаються підтвердженими.
- /documents та /documents/[slug] – дозволений каталог вихідних Markdown-документів; читання через сервер і датований fallback.
- /join – зрозумілі маршрути участі, локальна форма підготовки Markdown. Вона не надсилає й не зберігає текст у сервісі.
- GET /api/catalog – публічний нормалізований JSON із джерелом і датою.

## Закритий розгляд карток

Рекомендований шлях починається з `/join/chat`. AI-асистент допомагає сформулювати й уточнити ідею. Автор може підготувати ту саму картку вручну на `/join` або в редакторі. В обох випадках він переносить лише погоджені заголовок і текст у `/join/card` та підтверджує приватне передавання. Після цього потрібно зберегти адресу разом із фрагментом після `#`. Це ключ доступу до однієї картки. Без нього відновити доступ через обліковий запис неможливо. Черга зберігає хеш ключа, поточний текст і перебіг розгляду.

Рецензент входить на `/review`. Для локальної розробки при першому відкритті кабінету застосунок генерує ключ у `%LOCALAPPDATA%/uagp-private-review/reviewer.key` на Windows або `~/uagp-private-review/reviewer.key` за відсутності LOCALAPPDATA. Відкрийте файл у локальному редакторі. У пілоті рецензенти використовують спільний ключ. Окремих облікових записів або персонального журналу рецензентів поки немає.

Для production задайте `UAGP_QUEUE_DIR` на постійному локальному диску одного сервера поза вебкоренем і `UAGP_REVIEW_KEY` з 32 випадкових байтів у hex. Обмежте доступ до каталогу користувачем застосунку, використовуйте HTTPS і резервне копіювання SQLite через засоби SQLite. Копія бази містить приватні картки. Секрети передавайте через середовище сервера. Зміна ключа та перезапуск відкликають доступ за старим ключем.

Після запиту уточнення автор може подати нову версію. Кожну таку версію рецензент перевіряє знову. Схвалення відкриває авторові окремий дозвіл на оприлюднення. Лише після цього рецензент отримує дію публікації. Для неї потрібен окремий `UAGP_QUEUE_GITHUB_TOKEN` з дозволом Issues: write тільки в ailubes/uagp. У GitHub передаються заголовок, текст і технічна позначка зв’язування. Приватний ключ автора та нотатки рецензента залишаються в черзі.

Якщо GitHub не повернув остаточну відповідь, картка залишається у стані звірки. Знайдіть відповідний Issue і введіть його номер в кабінеті. Сервер звіряє номер, заголовок, текст і позначку. За відсутності підтвердженого запису дослідіть результат запиту на стороні GitHub перед будь-яким ручним повтором. Це запобігає дублюванню після тайм-ауту.

Інтеграційний тест запускається після `npm run build` командою `npm run test:queue`. Він створює тимчасову базу та замінює GitHub на локальну тестову реалізацію.

## Дані й безпека

Серверні запити обмежені фіксованим репозиторієм ailubes/uagp, кешовані (5 хвилин каталог, 10 хвилин документи), мають timeout і пагінацію. Якщо GitHub недоступний або повертає неповну/невалідну відповідь, застосунок може відобразити датований архів. Не підміняє помилки порожнім набором. У браузері немає GitHub-токена. HTML із Markdown не виконується, небезпечні URL блокуються, зовнішні зображення не завантажуються автоматично. Імена призначених виконавців – лише відкриті поля GitHub, не підтверджені громадянські ролі.

Знімки web/data/catalog.json і web/data/documents.json містять джерельні дати та SHA документів. Оновлені копії окремих документів мають власну дату. Під час релізу оновіть знімок, якщо джерельні документи змінені. Робочі гілки відокремлено від main. Сайт не проводить голосування, не підтверджує громадянство, не приймає адміністративні заяви. Публікація і коментарі в першій версії залишаються в GitHub. Незалежний OIDC, Participation Steward та remote MCP – окремі майбутні роботи.

## Перевірка

    npm run typecheck
    npm test
    npm run build
    npx playwright install --with-deps chromium
    npm run test:e2e

Playwright запускається в детермінованому режимі знімка; перевіряє desktop/mobile, пошук, чернетки, локальне завантаження та джерела документів. Скриншоти зберігаються у test-results, звіт – playwright-report. Потрібна окрема перевірка live GitHub API та візуальний огляд перед релізом. Немає підтвердження відповідності WCAG до повного аудиту.

Поточний пакет використовує підтримувані лінійки Next.js 16 / React 19 / TypeScript 5.9. Локальний запуск і CI встановлюють залежності через npm ci з package-lock.json.
