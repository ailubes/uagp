# WEB-001 – межі наступного релізу

## Release gate

1. Збірка Next.js та TypeScript, unit та браузерні тести, перевірка скриншотів desktop/mobile.
2. Перевірка live GitHub API, кешу, rate limit, timeout, fallback, довгих PR/документів і помилкових URL.
3. Фіксація lockfile, аудит залежностей, перевірка CSP/заголовків для обраного середовища, WCAG 2.2 AA review.
4. Узгодити домен, власника/оператора та порядок підтримки. Публікація лише після окремого рішення. Метадані пошуку (robots) наразі noindex для review.

## WEB-002 – персональний простір, добровільна участь

Після погодження #13, #14, #19, #22 спроєктувати незалежний self-hosted OIDC із PKCE та server-side session, не Wesfin ID. Створення чернетки не є публікацією; користувач підтверджує публічну версію, модерація й незалежний перегляд. Не збирати політичний профіль, реєстр лояльності чи повні приватні AI-чати.

## WEB-003 – змістовний супровід

Participation Steward: реальна роль координатора, next action, причина затримки, запланований змістовний перегляд, аудит зміни відповідального, можливість добровільної допомоги й відмови від сповіщень. Не виводити фіктивний трекінг із самої GitHub активності.

## WEB-004 – практична співпраця зі спільнотами

SG-01: працювати з підтвердженими добровільними спільнотами, не вимагати переходу на платформу. Валідувати потреби перед кожною наступною функцією. Впровадження BYOAI/MCP після перевірки безпеки й згоди, без права LLM на автономні владні чи публічні дії.
